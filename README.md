# SAWT API — إزالة الموسيقى مع الحفاظ على الكلام

هذه نسخة API فقط؛ لا تحتوي على واجهة موقع. مبنية باستخدام FastAPI وDemucs وFFmpeg.

## التوثيق التفاعلي
بعد تشغيل الخدمة افتح `/docs` لتجربة الطلبات، أو `/redoc` لقراءة التوثيق.

## نقاط النهاية

- `GET /` — معلومات الخدمة.
- `GET /health` — فحص حالة الخدمة.
- `POST /api/jobs` — رفع فيديو بصيغة `multipart/form-data`، واسم الحقل `file`.
- `POST /api/jobs/url` — بدء المعالجة من رابط فيديو، بجسم JSON مثل `{"url":"https://..."}`. يدعم روابط YouTube العامة عبر yt-dlp وروابط الفيديو المباشرة العامة.
- `GET /api/jobs/{job_id}` — متابعة الحالة والتقدم. الحالات الممكنة: `queued`, `downloading`, `processing`, `done`, `error`.
- `GET /api/jobs/{job_id}/download` — تنزيل الفيديو بعد اكتمال المعالجة.

## مثال استخدام

1. أرسل `POST /api/jobs/url` مع JSON:

```json
{"url":"https://www.youtube.com/watch?v=VIDEO_ID"}
```

2. خذ `job_id` من الاستجابة، ثم استعلم دورياً عبر:

```http
GET /api/jobs/JOB_ID
```

3. عندما تصبح `status` مساوية لـ `done`، نزّل النتيجة عبر:

```http
GET /api/jobs/JOB_ID/download
```

## التشغيل محلياً

المتطلبات: Docker وDocker Compose. من مجلد المشروع نفّذ:

```bash
docker compose up --build
```

أو ثبّت Python 3.10 وFFmpeg ثم:

```bash
pip install -r requirements.txt
uvicorn app:app --host 0.0.0.0 --port 8000
```

## ملاحظات مهمة

- هذه نسخة أولية؛ قائمة المهام محفوظة في الذاكرة، لذلك قد تضيع حالة المهام عند إعادة تشغيل الخدمة أو تغيير النسخة.
- يلزم خادم بذاكرة ومعالج كافيين؛ فصل الصوت للفيديوهات الطويلة عملية ثقيلة وقد يحتاج خطة مدفوعة.
- لا تكشف الخدمة للعامة دون إضافة مصادقة ومفاتيح API وحدود استخدام ومراقبة وتنظيف للملفات.
- استخدم فقط المحتوى الذي تملكه أو لديك إذن بمعالجته. قد لا تعمل روابط YouTube الخاصة أو المقيدة.
- استخراج vocals لا يضمن إزالة كل الموسيقى أو بقاء الكلام بجودة كاملة في جميع الحالات.
